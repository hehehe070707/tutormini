# TutorMini · 家教平台（微信小程序版）

这是 Qt 桌面版 `D:\qt\TutorFinal` 的微信小程序翻译版，用**原生小程序（JS + WXML + WXSS）**重写，
功能、业务规则、文案与 Qt 版一一对应，原项目没有改动（只读参考）。

**架构（行业标准版）**：业务数据（用户、订单、发布、聊天、评价）全部存在**后端数据库**里，
后端代码在 [`server/`](server/README.md)；小程序端不存业务数据，`wx.storage` 里**只有一枚登录令牌**。
手机、模拟器、任何设备访问的都是同一份数据。

## 打开方式

1. **先起后端**（业务数据都在那儿，不起后端小程序连不上）：

   **最省事**：双击项目根目录的 **`启动后端.cmd`**，会弹出一个黑窗口（那就是后端，别关）。
   想让它**开机就自己起来**（以后模拟器和手机都不用管）：双击一次 **`安装开机自启.cmd`**。

   或者用命令行：

   ```powershell
   cd server
   node server.js          # http://127.0.0.1:3000，零依赖，不需要 npm install
   ```

   窗口里会打印后端地址、数据库位置和**真机调试用的局域网地址**，看到「家教平台后端已启动」就是好了。

2. 微信开发者工具 → 导入项目 → 目录选 `D:\LZM\TutorMini`。

   > 常见问题：一进小程序弹「连不上后端」，控制台还有 3 个报错 —— 就是那 3 个请求（探活 + 老师列表 + 科目）都没连上后端。
   > 双击 `启动后端.cmd`，再在弹出的提示框里点「重试」就好，不用重新编译。

3. AppID 填自己的（`project.config.json` 里已写 `wxaa4fb30710adfcc2`）；
   开发阶段在「详情 → 本地设置」勾上**不校验合法域名**（`urlCheck` 已经是 `false`）。
4. 编译后直接进**第一页**（不用登录）：大家发的单都能随便看；
   只有**发布需求、接单、聊天**这些动作才弹身份确认——选「学生 / 老师」后建账号（姓名 + 密码），登录完自动回到刚才那一步继续做。
   未登录时底部导航是 发单 / 我的；登录后按身份变成学生端或老师端的那套 Tab。
5. **真机预览**：手机和电脑连同一个 WiFi，数据立刻和模拟器同步（同一份后端）。
   地址不用自己猜 —— 双击根目录的 **`查看本机IP.cmd`**，它会打印电脑当前的局域网 IP、探活后端，
   并直接告诉你 `utils/config.js` 里那一行该怎么写。换电脑 / 换 WiFi / 重连校园网后电脑 IP 会变，重跑一次即可。

## 常见问题（开发者工具）

| 现象 | 原因 / 怎么修 |
| --- | --- |
| 一进小程序弹「连不上后端」，控制台 3 个红字 | 后端起没起来。这 3 个请求（探活 `/health` + 老师列表 + 科目）都没连上。双击 `启动后端.cmd`，回小程序点提示框里的**重试**即可（不用重新编译） |
| `request:fail ERR_CONNECTION_REFUSED` | 同上：后端没在跑（或端口不是 3000） |
| `request:fail ERR_CONNECTION_TIMED_OUT`（真机） | 手机连的这个地址上没有主机，或校园网把手机和电脑隔开了。双击 `查看本机IP.cmd`：IP 对不上就改 `utils/config.js` 第二个地址；对得上但手机浏览器也打不开，就是 AP 隔离，走 `穿透后端.cmd` 或手机热点 |
| `request:fail url not in domain list` | 「详情 → 本地设置」里勾上**不校验合法域名**（`project.config.json` 里已设 `urlCheck:false`，勾选框被手动改过才会这样） |
| `getLocation:fail` / 定位失败 | 小程序后台没开通「用户地理位置」接口权限（开发阶段可在工具里手动允许）。不影响浏览下单，只是不按距离筛附近、不显示距离 |
| `login:fail` | AppID 不对或没登录开发者工具。不影响用「姓名 + 密码」登录；配好 `WX_APPID`/`WX_SECRET` 后才有微信免密登录 |
| 真机上看不到数据 | 见下面「手机（真机）怎么用」：手机要和电脑在同一个 WiFi；`utils/config.js` 第二个地址用 `查看本机IP.cmd` 打印的局域网地址 |

## 手机（真机）怎么用

小程序是**客户端**，它不会去"启动"后端 —— 后端是台服务，得有人跑着它。规矩是这样的：

| 阶段 | 谁在跑后端 | 手机要做什么 |
| --- | --- | --- |
| 开发（现在） | 你的电脑（`启动后端.cmd`，或装了开机自启就一直是开着的） | 手机连**同一个 WiFi**，用开发者工具的「真机调试」扫码打开 |
| 上线（以后） | 云服务器，7×24 一直开着 | **什么都不用做**，所有手机连的都是云端同一份数据 |

开发阶段手机上怎么连（不用改代码）：

1. `utils/config.js` 里配了两个地址，**会自动按顺序试**：先试 `127.0.0.1`（模拟器用），不通就换第二个（手机用的局域网地址，现在是 `http://10.195.49.246:3000/api`）。
2. 换电脑 / 换 WiFi（校园网的 IP 一段时间就变一次）后，双击 **`查看本机IP.cmd`**，按它打印的地址改第二项 —— 别照抄文档里的 IP。
3. 手机和电脑要在同一个 WiFi。先用手机浏览器打开 `http://<那个IP>:3000/api/health` 试一下：能看到一串 JSON 就说明通了。
4. 手机浏览器也打不开，说明是网络限制（校园 WiFi 普遍开了「客户端隔离」，手机和电脑互相看不见）。两个绕过办法：
   - 最简单的：**用手机开热点，让电脑连手机的热点**，重跑 `查看本机IP.cmd` 拿新 IP，改 `config.js` 第二项；
   - 或者双击 **`穿透后端.cmd`**，用 Cloudflare 免费隧道把后端暴露成一个公网 https 地址（手机用 4G 也能连），地址脚本会自己填好，见下面「穿透」。

## 手机连不上时（校园网/公司网）

先双击 **`查看本机IP.cmd`**，它会把上面这些检查一次跑完（当前 IP、后端是否绑 `0.0.0.0`、探活结果、和 `config.js` 是否一致）。

想用穿透绕开校园网：双击 **`穿透后端.cmd`**（`cloudflared.exe` 已经放在项目根目录），
它会把本机 3000 端口变成 `https://xxxx.trycloudflare.com`，**并自动把地址写进 `utils/config.js`**
（`TUNNEL_BASE` 那一行），不用手改。然后微信开发者工具点一下「编译」就行。三点注意：

1. 隧道窗口要一直开着，关掉就等于穿透停止；每次启动的域名都不一样，脚本每次都会重新写一遍。
2. trycloudflare 的域名不是你的，加不进小程序后台的 request 合法域名 —— 开发阶段继续勾着「不校验合法域名」。
3. 穿透期间后端对公网可见，开发库里别放真实手机号/密码。

地址的尝试顺序是 **本机 `127.0.0.1` → 穿透地址 → 局域网 IP**：模拟器走第一条秒开，
手机在校园网隔离下走第二条，只有两条都不通才会去试局域网 IP（那条会干等 15 秒超时）。

常用脚本（都在项目根目录，双击就行）：

| 脚本 | 作用 |
| --- | --- |
| `启动后端.cmd` | 手动启动后端（窗口开着才有效） |
| `安装开机自启.cmd` / `取消开机自启.cmd` | 装上 / 取消「开机自动启动后端」 |
| `停止后端.cmd` | 停掉后端，释放 3000 端口 |
| `查看本机IP.cmd` | 打印电脑当前局域网 IP + 探活后端 + 对照 `utils/config.js`（手机连不上先跑这个） |
| `穿透后端.cmd` | 用 Cloudflare 隧道把后端变成公网 https 地址（绕开校园网 AP 隔离），并自动写进 `utils/config.js` |

## 数据层对应关系

### 存储划分（改造后的规矩）

| 存哪儿 | 存什么 |
| --- | --- |
| 后端数据库 | **唯一真实数据源**：用户（平台账号/老师）、订单、课次、发布单、聊天、收款退款、Agent 令牌与事件、会话令牌摘要、openid 绑定 |
| 小程序 wx.storage | **只有 `session_token` 一枚登录令牌**；定位、附近半径这些纯本机偏好在内存里 |
| 小程序内存 | 当前登录身份（`utils/session.js`）、定位、半径、页面数据（只用于渲染，不落盘） |

### 登录流程

1. 打开小程序：有令牌 → 后端 `/api/auth/me` 换身份（后端说了算）；没令牌 → `wx.login` 拿 code → 后端换 openid → 查绑定自动登录。
2. 没绑过账号才让用户选身份，用「姓名 + 密码」登录 / 注册；这次登录顺带把 openid 绑上，下次同台微信免密进。
3. 之后每个请求都带令牌，后端重新查身份、算权限、查归属——前端 storage 被改也没用。
4. 退出登录只作废这一台设备的令牌，别的设备照常在线。

| Qt 版 | 小程序版 |
| --- | --- |
| SQLite 七张表 + sessions | 后端同一套表结构（开发 SQLite / 上线 MySQL，见 `server/db/schema.js`） |
| `xxxChanged()` 信号 + `connect()` | 本机改完数据 `store.on('xxxChanged', fn)` 通知页面刷新；跨设备靠 `onShow` 重新拉数据 |
| 返回 bool / id，失败原因走 `QString *errorOut` | 返回 bool / id（异步），失败原因读 `store.lastError`，文案和原来一字不差 |
| 密码存 SHA-256 摘要 | 后端存 SHA-256 摘要（`node:crypto`），同样不落明文 |
| 会话令牌存本地文件 `session.token` | 后端只存令牌摘要，小程序端只存原文 `session_token`，有效期 90 天，多设备各一枚 |
| 桌面 `teachers.txt` 首次导入 | 后端首次启动写入示例老师（王数学 / 李英语 / 张物理） |
| 单机一个 SQLite 文件 | 所有人都连同一个后端 → 多端数据天然统一 |

## 保留的业务规则

- 学生 / 老师都是「姓名 + 密码」账号，同名同密码重复注册直接返回原账号。
- 价格是自由文本（`150 元/小时`、`200 元/次`、`面议`），接单时存价格快照；累计消费只累加开头的数字。
- 时段 = 未来 7 天 × 上午 / 下午 / 晚上，现算不落库；老师同时段不能被两人约，同一学生同时也段也不能约两位老师。
- 订单链路：学生发单 → 老师**投递简历**（不能一键接单，先写自我介绍发过去）→ 课先挂「待确认」
  → 家长看过简历点【确认接单】才**接单成功**（课变已确认）；家长点「换一位老师」＝这次投递作废，
  单子立刻回到「招募中」。
- 取消分两层：**没被接单之前**取消的是订单（发单的学生在【发单】页撤销，单子作废）；
  **已经被接了**取消的是预约 —— 老师和学生都能取消自己那一侧的课，取消后课变「已取消」，
  同时单子回到「招募中」，别的老师还能接。
- 首页只放"还得管"的单：【发单】页 = 招募中 + 待你确认；【接单】页 = 可接的单 + 进行中的课。
  已成交、已撤销、已取消的历史单都收在【我的】页（学生「我的发单历史」/ 老师「我接单的历史」）。
- 单边发单/接单：平台账号（学生端）发「求教需求」，老师看到合适的点【投递简历】把自我介绍发过去
  （不带简历后端直接挡，单子被这条申请占住），家长确认后才算接单成功；
  老师不能发单（后端也挡），学生也不能接单；没被接之前学生可自己撤销。
- 聊天：会话由 (学生 id, 老师 id) 唯一确定，未读红点 + 打开即已读，主界面「消息」上带角标。
- 聊天限条数：两人之间还没有「已确认」的课时，未成交时**轮流一条**（确认接单后不限），
  聊天页顶部会提示还能发几条。以后加支付/押金（上课前 3 天内取消扣押金）后，
  这两条 + 押金规则就是防乱取消的全部手段，不需要再加别的限制。
- 账号级隔离：订单、消息、聊天、统计都按当前登录账号过滤，接口做归属校验。
- 只看附近：登录（含自动登录）后自动定位一次，「发单 / 接单」页的单子只显示
  半径内（默认 **45 公里**，页面上可调 5/10/20/45/100/不限）的单；卡片上带直线距离，近的排前面。
  **定位和半径都只放在内存里**（冷启动重新取一次，不写 wx.storage），随请求发给后端，
  由后端做距离过滤和排序（`server/domain/nearby.js`）。
  没授权定位、或老数据没有坐标时不硬卡列表：照常显示 + 顶部一行提示（「开启定位 / 看全部」一键切）。

## 与 Qt 版不同的地方（都是平台差异，不是功能删减）

- Qt 版一打开就是登录页；小程序版改成**先浏览、后登录**（微信里点开就能看，别一进来就拦一道）。
- Qt 版没有定位，位置是手打的文字；小程序版加了 `wx.getLocation` 自动定位 + `wx.chooseLocation` 选点，
  发布/资料里的位置会连经纬度一起存库（`teachers.lat/lng`、`posts.lat/lng`），
  没手动选点的用自己的当前定位兜底，页面据此算距离、按半径筛（`utils/location.js` + `store.setNearbyKm`）。
- 底部导航用小程序**自定义 tabBar**（`custom-tab-bar/` + `wx.switchTab`）：同一格 Tab 按身份渲染（学生点进去是「发单 / 发单」，老师点进去是「接单」），学生端显示 4 项、老师端 3 项、访客 2 项。
- 切页性能：tab 页由系统缓存常驻，切 Tab 只是显示/隐藏（不再 `reLaunch` 重建整页）；页面刷数据统一放在 `onShow`（`onLoad` 不再刷一遍），数据订阅 `onShow` 注册、`onHide` 注销，藏在后台不做无用刷新。
- 表格（QTableWidget）改成手机上的列表卡片（左右分栏 + 操作按钮），信息字段一致。
- 弹窗（QDialog / QMessageBox / QInputDialog）用 `wx.showModal` 或页内自绘弹层。
- **数据存后端，不存本机**：业务数据全在 `server/` 的数据库里，小程序端 `wx.storage` 只留一枚
  `session_token`。所以换手机、清缓存、模拟器和真机同时开，看到的都是同一份数据；
  前端改本地缓存也拿不到别人的数据（每个请求都由后端按令牌校验身份和归属）。
